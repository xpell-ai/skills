# XAgent and Pulse

- Trace the current consumer through the existing Router adapter and service contract. In the XAgent Starter, use the `@xpell/xai-providers/aime` boundary and its documented endpoint, server-side project key and task hint. Pulse-specific composition and policies belong in Pulse. Verify the consumer's actual endpoint, Router profile, account, project and key binding. Keep key values out of chat, logs and browser configuration.
- Qualify the generic Agent flow offline with a mock Router first. Verify safe errors, stable operation identity across replay, persisted conversation and shared context across turns. Distinct operation IDs alone do not prove shared context. Match the relevant consumer contract and test a fresh restart when durability is in scope.
- A supervised live smoke requires a verified effective route/model and enforceable aggregate provider-cost cap before dispatch. Include all billable phases, output and thinking, retries and uncertain exposure. Count earlier settled spend when the grant is cumulative. Verify durable reservation before dispatch, sequential settlement where required, and no surprise fallback. Stop on ambiguous dispatch or incompatible authorization/profile. Reconcile usage, ledger, holds and budget after the authorized traffic.
- For a Pulse endpoint cutover, verify the target's supported funding path, funded target account, and compatible launch/grant mode before switching. A Google identity profile and a paid development profile may have incompatible launch flags. Exercise the new path with approved traffic and preserve the old endpoint, store and config for rollback until cutover is verified. Retire the old service only after separate applicable authorization.
